# Athletiq Product Principles & Execution Guide

This document serves as the permanent source of truth for the Athletiq platform. It outlines the philosophy, architecture, UI hierarchy, and design rules that must be followed strictly during development.

**Core Rule:** Do NOT "design the app" blindly. Everything must be broken down into: Philosophy, System Architecture, UI Structure, and Component Improvements. The User is the Product Visionary; Antigravity is the Execution Engine.

---

## 1. Product Philosophy

### Athletiq IS:
* An athlete operating system
* A preparation optimizer
* An athlete memory
* A low-friction development system
* A performance intelligence platform

### Athletiq IS NOT:
* A WHOOP clone
* A readiness score addiction
* A simple calorie tracker
* An overwhelming analytics dashboard
* A guilt/shame productivity app

**The Biggest Differentiator:** Preserving and understanding the story of becoming great. We are building athlete intelligence, athlete memory, athlete evolution, a preparation system, and decision support. This is much bigger than HRV and sleep scores.

---

## 2. System Architecture (The 4 Core Layers)

Every feature in Athletiq falls into one of these four fundamental layers:

### 1. Inputs (Data Collection)
What data comes in: Watch data, workouts, sleep, meals, soreness, mobility, lifting, race results, reflections.

### 2. Intelligence Layer (Calculation & Synthesis)
What Athletiq calculates: Preparation completeness, biggest opportunity, trends, correlations, risk patterns, recovery suggestions.

### 3. Action Layer (The "What Next")
What the athlete should do next: Mobility routines, hydration, sleep consistency, fueling, recovery modalities, breathing work.

### 4. Memory Layer (The Moat & Emotional Core)
Long-term athlete archive: Races, breakthroughs, injuries, training blocks, reflections, gear (shoes), race videos, lessons learned ("what worked"). Most apps miss this layer entirely.

---

## 3. UI Hierarchy & Intent

**The Core Issue to Avoid:** Too much equal visual importance.

The Home Screen must ONLY answer:
1. What matters most today?
2. What should I do?
3. Am I building momentum?

It must NOT contain: Giant dashboards, huge data walls, or endless metrics. 
*Good categories should visually fade. Low categories should command attention.*

---

## 4. Prioritized Execution Flows

Features must be built one incredible flow at a time, in this strict priority order:

1. **Preparation Pillars (The Foundation):** Requires clean visuals, meaningful calculations, detail drill-downs, and real reasoning.
2. **Review Your Day (Retention Mechanic):** Must be fast, satisfying, low-friction, and intelligent.
3. **Timeline / Athlete Memory (The Moat):** Where Athletiq becomes emotional.
4. **Fuel Lens (Viral Differentiator)**
5. **Athlete Evolution (Psychological Retention)**

---

## 5. Real Scoring Systems

**Rule:** Do NOT fake scores. Every pillar must have a real system behind it.

Every scoring pillar requires:
* Inputs
* Weights
* Thresholds
* Confidence levels
* Missing data handling

*Example (Mobility Score):*
* **Inputs:** sessions/week, soreness, skipped cooldowns, ROM tests, injury history.
* **Weighted Model:** Consistency (50%), Soreness (25%), Recovery Adherence (25%).

---

## 6. Permanent Design Rules

### Data Rules
* No giant scores.
* No overwhelming graphs.
* No unnecessary notifications.
* No equal emphasis everywhere.

### Visual Rules
* **Attention:** Red / Orange.
* **Calm:** Green.
* Detail should be hidden behind taps.
* Use thin bars and minimal typography.
* Premium dark UI aesthetic.

### Product Rules
* The athlete should feel proud.
* The app serves the athlete, not the other way around.
* Low friction first.
* Always explain the *WHY*.
* Show momentum, not perfection.
